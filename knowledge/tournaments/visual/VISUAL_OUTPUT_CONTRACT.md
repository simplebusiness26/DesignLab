# Visual Output Contract

Every contestant returns:
1. Creative direction
2. Visual thesis
3. Hero-screen specifications
4. Typography
5. Colour
6. Spacing/rhythm
7. Composition
8. Component treatments
9. Surfaces/borders/elevation/depth
10. Iconography
11. Imagery/illustration
12. Motion appearance and feedback
13. State styling
14. Accessibility
15. Proposed design tokens
16. Implementation implications
17. Strengths
18. Risks
19. Anti-caricature check
20. Full-app HTML visual prototype specification
21. Full-app context verification

## Mandatory review context
Visual tournament candidates must follow `knowledge/prototypes/FULL_APP_HTML_STANDARD.md`.

A visual direction may not be judged only on a detached hero screen. It must be applied inside a recognisable, navigable representation of the inspected product so the user can see how the visual system behaves across the surrounding app and inside the target experience.

The full-app shell, routes, capabilities and relationships must come from Product Truth. Simulated data is allowed; invented product functionality is not.

The visual contestant may restyle the approved UX and the surrounding presentation needed to judge coherence, but must not quietly redesign or add unrelated product behaviour.

A visually impressive isolated screen that does not feel coherent inside the full product fails the review contract.
