# Message Switchboard

## Persona
Jordan Singer-inspired systems lens

## Core thesis
Treat conversations as one coherent information system with transparent deterministic grouping/search/filter patterns and reusable conversation states.

## Structure
- Messages landing surface with Friends, Managers and Message Boards available through a clear organisation pattern.
- Conversation rows show identity, useful preview, timestamp/recency and unread state.
- Thread keeps conversation history dominant.
- Composer remains pinned immediately above the software keyboard.

## Primary interaction
Tap a row to open the thread. Back returns to the same list context/scroll position.

## Persona-specific treatment
- Automate repetition before automating judgement.
- When an interface can adapt, make the adaptation legible, deterministic where possible, and easy to override.
- Design systems should be executable systems of rules rather than static collections of screenshots.
- Prototype real behavior early; dynamic interfaces are hard to judge from prose alone.

## Required states
Populated, empty category, loading, send pending, send failure, long message, keyboard open, reduced motion.

## Accessibility
Important actions have visible alternatives; no state depends only on colour or gesture.

## Trade-off
This direction intentionally optimises systems thinking and may sacrifice some of the strengths offered by the other persona lenses.

## Product-truth check
No new backend capability is required by the primary proposal.
