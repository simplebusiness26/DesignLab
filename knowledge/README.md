# DesignLab 2.0 Knowledge System

DesignLab 2.0 separates deep research from runtime context.

## Core pipeline

`evidence → research dossier → compact persona pack → product truth → feature packet → independent tournament → human selection → synthesis → approval lock → implementation → QA`

## Runtime rule

Never load the whole research archive into a routine model call. Load only:
- the relevant `PERSONA_PACK.md`;
- the smallest relevant slice of Product Truth;
- the current Feature Packet;
- relevant brand/design-system rules.

Research dossiers and source ledgers are audit/maintenance material.

## Human approval gates

1. Four UX concepts are produced independently.
2. The user reviews them and records preferred parts.
3. Opus synthesises one coherent final UX.
4. The user approves and locks UX.
5. Four visual directions are produced against the same locked UX.
6. The user reviews them and records preferred parts.
7. Opus/visual synthesis creates one coherent final visual system.
8. The user approves and locks visual design.
9. The application is implemented once, then compared against the approved specification.

## Model-efficiency rule

- deterministic scripts establish facts;
- Sonnet performs repeatable specialist work;
- Opus resolves high-value ambiguity and synthesis;
- Fable is reserved for visual work where visual capability materially changes the result.
